# 透明度报告

本文件面向使用者与审查者，说明官方 RayaTrainer 发布包里那一个编译后的 `RayaTrainer.Agent.dll` 做什么、需要哪些权限、对外暴露哪些能力类别，以及如何自行核验发布产物。它与 `docs/SECURITY.md`（源码边界与安全边界）互补，只描述允许的产品语义与核验方法，不列举具体内存地址、签名或可直接复现的滥用路线。

## 1. 混合源码说明

- 面向用户的应用外壳（App/UI/Web）、产品语义合同、设置与公共测试开源，可独立克隆、编译和审查。
- 可运行的 Native Agent 的内存访问、Hook、地址解析与游戏线程执行实现不在公共源码中，只以官方编译二进制随 Release 提供。
- 源码克隆只能编译“外壳”。缺少官方 `RayaTrainer.Agent.dll` 时，外壳会明确提示“缺少官方运行时组件”，并且不会尝试自行生成、替代或下载未知 DLL。
- 只有正式 Release 包内的官方二进制才具备可运行的修改能力。

## 2. DLL 权限与联网声明

- Agent DLL 由 App 在**本机**注入到用户自己启动的游戏进程，仅在**本地单人**游戏内工作。
- Agent **不主动联网**：不建立出站网络连接、不上传遥测、不下载远程代码或配置。
- App 与 Agent 之间只通过**本机命名管道**通信；该管道使用仅限当前登录用户（对象所有者）的安全描述符，拒绝远程客户端和同名实例抢占。
- Agent 不修改游戏文件、不写注册表、不安装系统服务或驱动；效果只作用于当前游戏进程的运行时状态，进程结束即消失。
- 无法证明当前处于受支持的本地单人会话时，Agent 拒绝一切副作用请求（fail-closed）；离开该范围时会撤销已生效的运行时效果与待执行请求。

### 2.1 Web 遥控可选组件（局域网 HTTP，独立程序 WebMini）

- 主程序 **不内置任何 Web 服务**：不编译/加载 ASP.NET Core，启动不监听任何网络端口，运行库要求仅 .NET 8 x86 Desktop Runtime。
- 局域网手机遥控由**独立可选组件 `RayaTrainer.WebMini`** 提供（与主程序同一 Release 作为可选附件发布；不运行它则完全不接触网络）：基于 ASP.NET Core 的本地 HTTP 服务，默认端口 8787（可在其窗口修改，也可绑定到具体网卡），启动即服务，窗口内显示配对二维码，供同一局域网的手机浏览器访问功能面板。
- WebMini 运行时，HTTP 服务默认监听本机所有网卡的 8787 端口（可在窗口缩小到指定网卡）；首次连接需在其窗口内弹窗确认设备配对（默认焦点在「否」，未确认或异常一律拒绝），确认后下发仅存于内存的 bearer token（进程结束即失效），全程无 TLS。
- **不建立任何出站网络连接**：不向 EA、GitHub 或任何外部服务上报数据、不下载远程内容；只被动监听本机端口，等待用户主动发起的局域网连接。如需进一步隔离，可在系统防火墙中限制 8787 端口的作用域。
- WebMini 与主程序同时运行时，由协议指纹门禁裁决（同指纹接管、旧指纹拒绝），先到先得；决策记录见 ADR 0033（修订 ADR 0032：从“默认关”升级为“默认不含”）。

## 3. 命令能力类别

Agent 对外只按“类别”提供能力，且副作用类别一律经本地单人会话准入：

- **状态与能力查询**：连接探活、运行时状态、游戏模式、能力协商、产品结果读取。这些在被拒绝状态下仍可用于诊断。
- **产品语义修改**：以“产品意图”提交的规范化修改（如资源、单位相关的产品化操作），由 Agent 内部按产品定义执行并回报结果。
- **预设投影执行**：把用户在 App 中保存的增援/秘密协议预设作为整体意图执行。
- **游戏内 Overlay**：对局内选择已保存预设并一键执行，展示提交/执行/观察结果。

不属于公共能力、也不作为通用远程服务对外提供的：任意进程内存读写、任意脚本执行、底层地址/指针/哈希调用入口。此类底层能力即使存在于内部实现，也受本地单人会话准入约束，并且不构成可被第三方外壳任意驱动的通用接口。

## 4. 如何核验官方发布产物

正式 Release 附带校验材料，建议按下述步骤核验后再运行：

1. **包哈希**：对照 Release 资产中的 `SHA256SUMS.txt` 校验下载的压缩包，例如 `sha256sum -c SHA256SUMS.txt`。
2. **Agent 来源清单**：包内 `agent-release.json` 记录该 `RayaTrainer.Agent.dll` 的 `file`、`architecture`（x86）、`protocolMajor`、`buildId`、`sha256` 与 `signed` 状态。
3. **DLL 哈希比对**：自行计算 DLL 的 SHA-256（如 `Get-FileHash -Algorithm SHA256`），与 `agent-release.json` 中的 `sha256` 一致即证明二进制未被替换。
4. **签名（若提供）**：当 `signed` 为 `true` 时，可用系统工具核验 Authenticode 签名主体与时间戳。默认发布路径为 unsigned（ADR 0031 §3 2026-08-02 修订）：SHA-256 清单是唯一防篡改门禁，无签名证书即不签名；`signed` 字段如实记录签名状态。
5. **架构**：本程序为 32 位，Agent 必须是 x86；请确认目标机安装的是 x86 版 .NET 运行库（framework-dependent 包）。

`buildId` 仅用于透明度与诊断展示，不改变接管策略：相同协议 major、不同 buildId 的已注入 Agent 仍允许接管并提示构建不同。

### 4.1 注入资产内容可审计

部分功能通过 Agent 向游戏进程注入一个**运行时资产包**（标准 Sage 引擎资产流，进程结束即消失，不落盘、不改游戏文件）。其全部内容可审计：

- **资产声明源码公开**（`src/RayaTrainer.Core/RuntimeAssets/AttributeModifiers/Mod.xml.source`）：48 个模板的名称、数值与语义一目了然，没有其他内容来源；二进制流由该源确定性生成（`scripts/build-runtime-assets.ps1`），生成过程详见 `docs/runtime-assets.md`。
- **哈希合同公开**（同目录 `asset-manifest.json`）：锁定八个流（Game 6/Uprising 双格式）的 SHA-256 与全部模板 InstanceID；自备 RA3 MOD SDK 重建 Game 6 流并比对哈希，即可确认官方内嵌内容与公开源一致。
- **无外部加载槽位**：修改器只从自身程序集内嵌资源释放并加载该包，不存在从磁盘目录加载自建包的开关；自建流不会被加载。

## 5. 报告问题

如发现准入绕过、未授权接口或发布产物来源不一致，请通过仓库的私密安全报告渠道联系维护者（见 `docs/SECURITY.md`）；请勿公开提供可直接复现滥用的细节。
